# 独立客户端边界与后端验证原型

设计 v0.2 · 2026-10-09。产品确定为独立 3D 客户端、多人在线、面向 Steam。当前聚焦牌局后端设计，不开始 3D 建模、引擎工程或客户端实现。

## 1. 客户端暂时只确定契约

Unity、Unreal 等引擎的最终选择取决于制作团队、画面、平台、工具链与许可成本，另行评估。后台采用 .NET 不要求客户端采用同一语言，也不要求把图形引擎加载到牌局服务器。

| 客户端职责 | 与后端的约定 |
| --- | --- |
| 角色、座位与场景 | 绝对 SeatId 整场稳定；镜头变化不改变行动顺序 |
| 牌面与牌背 | 只展示服务端有权下发的 CardId；对手隐藏牌不是发下来后再盖住 |
| 拿牌、发牌、换牌动画 | 消费已确认事件；中断、跳过或重连后可直接重建当前画面 |
| 下注与改航输入 | 提交意图与命令 ID，不提交计算后的新筹码或所需下一张牌 |
| 行动倒计时 | 依据服务器期限显示；收到恢复／续时事实时更新，不靠帧数裁决 |
| 本地预测 | 可预测按钮按压和选择效果，金额、翻牌与结算等待权威确认 |
| 声音、语音、移动或表情 | 分别定义同步与隐私；本轮不将这些系统加入牌局核心 |
| Mod 表现资源 | 按房间允许内容加载；不会因为安装资源包就获得规则写入或私牌读取能力 |

牌局回放和 3D 动画回放是不同产物：前者需要规则版本、事件和可授权事实，后者可按当前场景重新表现。不能为了动画录制把整副牌保存到普通客户端日志。

## 2. 先做可验证后端，再接最终表现

后续最小验证原型可以使用命令行驱动器或一个只有按钮和牌号的原生测试客户端；这只是调试入口，不改变产品的 3D 方向。当前不实现该原型，也不再以 React 页面作为产品交付。

原型应能让五个相互隔离的身份各自连接，逐动作查看自己的合法视图，完成整个 12 局；能在任一操作时断线、重试、切换服务节点并恢复。机器人与真人最终经过同一动作校验入口。

| 阶段 | 未来产物 | 完成依据 |
| --- | --- | --- |
| B0 契约 | 领域类型、标准配置、包能力、消息与可见性表 | 本设计各规格一致；标准规则与自定义参数边界清楚 |
| B1 纯核心 | 无引擎依赖的单步规则库 | 固定牌序／动作金样、性质测试、非法命令无副作用；参数配置验证 |
| B2 持久房间 | 命令提交、租约、回执、恢复 | 双节点竞争与故障注入通过，私牌不泄漏，费用不重复 |
| B3 Steam 身份 | 受控测试 AppID 的身份联调 | 服务端验证真实票据；身份、会话、控制权与席位分别处理 |
| B4 参数 Mod | 规则包清单、规范化配置摘要、版本准入 | 不同配置不混房；原版本可恢复；非法包无法开始比赛 |
| B5 后端候选版本 | 运维、容量、安全与恢复记录 | 达到容量文档中约定的目标，未解决高风险故障阻断发布 |
| C1 3D 客户端联调 | 选定引擎的真实场景与操作 | 渲染表现不改变规则；网络丢包、动画卡顿和重连仍可继续 |

美术与交互制作可以并行规划，但这里不规定模型面数、材质、骨骼、镜头或渲染管线。

## 3. 必须提前约定的客户端联调场景

- 加注控件分清“本次投入”和“本轮累计”；短额全下不被客户端误算成完整加价。
- 改航目标是公共位置，前人替换后自己的确认文案必须更新；冻结费用不随动画或前人付款变化。
- 全下者保留奖池资格与隐藏底牌，只有全部结算后才能标记淘汰。
- 已提交动作后立刻退出或掉线，回来仍是原牌与原费用；无法通过中断换一个结果。
- 动画落后时允许跳到最新可见状态，不能等待某个玩家动画 ACK 才继续全桌。
- 官方服务恢复时显示恢复中及权威计时变化；个人断线则按正常规则计时。
- 标准房拒绝不兼容的规则包，自定义房在准备阶段清楚展示差异，开局后版本固定。
- 其他玩家、观众、录屏辅助、日志、机器人和 Mod 各自只取得其允许信息。
